# Fixture corpus

Synthetic label images with exact ground truth, generated by
`tools/generate_fixtures.py` (`make fixtures`). Evaluated by `tools/evaluate.py`
(`make evaluate`). **Do not edit anything here by hand**: change the fixture
table in the generator and regenerate.

| Path | What it is |
|---|---|
| `labels/<id>.png` / `.jpg` | The label image. 1000 × 1400 px — below the pipeline's working size (`TARGET_LONGEST_EDGE`, 2600 px), so a fixture is upscaled rather than shrunk; shrinking is the direction that costs ink, and the warning is the smallest type on the label. JPEG only for the noise/blur variant (noise does not compress in PNG, and a photo arrives as JPEG anyway). |
| `labels/<id>.<ext>.ocr.json` | Sidecar: every word drawn, its box in *saved-image* pixels, a synthetic confidence (0.97–0.99 clean, 0.84–0.93 degraded), and a `quality` block. Replayed by `extraction/providers/stub.py`. Ground truth, not a recording of an OCR run. A live OCR run reports boxes in the rescaled space instead; each mode is internally consistent and nothing compares boxes across them. |
| `expected.json` | Per fixture: the application record, the verdicts a *correct* tool may return per field (`allowed`), graded warning checks, a one-line `why`, and tags. |
| `batch_manifest.csv` | The whole corpus as a batch manifest: one row per fixture, `filename` = image basename, columns per `api.batch_models.MANIFEST_COLUMNS`. Generated from the same entries as `expected.json`, in the same run, so it cannot drift. Upload it with every image in `labels/` and all rows pair. |
| `batch_manifest_with_issues.csv` | Six rows with exactly three deliberate defects (below). |
| `fonts/` | Vendored fonts with their licences (below). |

## The broken manifest

`batch_manifest_with_issues.csv` is built from the first four fixtures. Pair it
with **the images it names** (`old_tom_compliant.png`, `brand_two_lines.png`,
`shared_line_abv_net.png`, `brand_twice_bottler.png`) and the backend reports
2 matched pairs and exactly three issues, one of each kind:

| Row | Defect | Reported as |
|---|---|---|
| 4 | names `missing_label.png`, which does not exist | `row_without_image` |
| 5 | `brand_twice_bottler.png` with an empty `brand_name` | `invalid_row` (no extra `image_without_row` for that image — the row-side issue already explains it) |
| 6–7 | the `shared_line_abv_net.png` row, twice | `duplicate_row` (neither row used) |

`tests/test_batch_eval.py` pins this against `api.manifest` itself, so a
fourth, accidental defect fails the suite rather than silently making "the UI
showed every issue" unfalsifiable. Uploading *all* corpus images with this
manifest adds an `image_without_row` for each unnamed image, by design.

## Reading `expected.json`

- `fields.<id>.allowed` is a **set**. `["MATCH"]` means anything else is a false
  flag; `["REVIEW", "MISMATCH"]` means the label is non-compliant on this field
  and the tool must flag it, at whichever level its evidence supports — MATCH
  would be a false negative. `["REVIEW"]` alone is used where the field is
  absent from the label: not-found is never MISMATCH. `["MATCH", "REVIEW"]`
  marks a judgment call (case-only brand difference; centilitres).
- `fields.<id>.elevated` (optional) asserts `FieldResult.elevated` — used for the
  warning-absent fixture, where the raised prominence *is* the finding.
- `checks` grades the two binding warning checks (`header_capitalisation`,
  `text_accuracy`). Advisory checks are measurements and are not graded.
- `compliance` is derived: `compliant` (all MATCH), `non_compliant` (at least
  one field forbids MATCH), or `judgment`.
- `warning_title_case_low_contrast` allows `["REVIEW"]` and nothing else, on
  purpose. Its header is systematically miscapitalised, so
  `header_capitalisation` must still FAIL, but the quality gate has flagged the
  image, and on a flagged image the typographic assertion is withdrawn. With
  the degraded-image guard: REVIEW. Without it: MISMATCH. Widening the set
  would make the fixture pass either way, which is the failure mode it exists
  to prevent.

## The `quality` block

Each sidecar carries the image-quality assessment **measured by
`extraction.pipeline.preprocess` on that exact file**, not an invented score.
The stub replays it, so a stub-mode run sees the same assessment a real
submission would, and the warning strategy's degraded-image guard — which
withdraws a typographic assertion to REVIEW when the gate has flagged the
image — fires identically in both modes. Without it, every stub-mode image
would look pristine and `warning_title_case_low_contrast` would grade
differently by provider.

This is the one place the generator depends on the code under test. The trade
is deliberate and narrow: text and geometry remain independent ground truth,
and only a measurement of pixels comes from the pipeline. Fabricating a
plausible score would be worse — the guard would then fire off a number nobody
measured. Regenerate the corpus whenever the quality metric changes.

Horizontal word extents come from Pillow's `textbbox` on the word; vertical
extents are the font's cap-to-descender box at that size, so every word on a
line has the same height, as OCR engines report it. On the rotated variant each
box is the axis-aligned bound of the rotated word.

## Fonts

All three families are SIL Open Font License 1.1, taken unmodified from the
npm packages published by the Fontsource project (which repackages Google
Fonts), version 5.3.0, `latin` subset, WOFF format. WOFF rather than WOFF2
because FreeType reads it without Brotli.

Families were chosen partly because **none declares a Reserved Font Name**.
Fontsource ships subsetted files, and a subset is arguably a Modified Version
under the OFL, which may not use a reserved name; choosing RFN-free families
avoids the question. The fonts are bundled with the repository's test data,
not sold, which the OFL permits.

Roles: Open Sans Regular for body text and the warning body; Open Sans Bold for
class/type and the `GOVERNMENT WARNING:` header (bold as § 16.22(a)(2)
requires, so the advisory bold check has a real contrast to measure); Libre
Baskerville Bold and Oswald Bold for brand display type.

## Determinism

Regenerating on the same Pillow/FreeType build reproduces every file byte for
byte (random choices are seeded from the fixture id via SHA-256). A different
FreeType version may rasterise glyphs, and therefore boxes, slightly
differently; `expected.json` is pure data and is checked for exact currency by
`tests/test_fixtures.py`. Generated with Pillow 12.2.0 / FreeType 2.14.3.
